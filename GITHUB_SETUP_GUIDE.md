# 🚀 Настройка обновлений через GitHub

## 📋 Обзор системы

Sims 4 Mod Installer теперь поддерживает автоматические обновления через GitHub Releases. Это позволяет:
- Автоматически проверять обновления при запуске
- Скачивать и устанавливать новые версии
- Управлять режимом технических работ
- Отслеживать уникальные устройства

## 🛠️ Настройка репозитория

### 1. Создание репозитория на GitHub

1. Зайдите на [GitHub](https://github.com) и создайте новый репозиторий
2. Назовите его `sims4-mod-installer` (или ваше название)
3. Сделайте репозиторий публичным для бесплатного использования API
4. Инициализируйте README.md

### 2. Настройка программы

Откройте файл `sims4_mod_installer.py` и измените строки:

```python
# GitHub настройки
self.github_owner = "your-username"  # Измените на ваш GitHub username
self.github_repo = "sims4-mod-installer"  # Измените на ваш репозиторий
```

Замените `your-username` на ваш никнейм на GitHub.

### 3. Загрузка кода на GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/your-username/sims4-mod-installer.git
git push -u origin main
```

## 🔄 Настройка автоматических релизов

### 1. Создание GitHub Actions

Создайте папку `.github/workflows` в корне репозитория и добавьте файл `release.yml` (уже создан).

### 2. Настройка токена

1. Зайдите в Settings → Developer settings → Personal access tokens
2. Создайте новый токен с правами `repo`
3. Добавьте токен в Secrets репозитория:
   - Settings → Secrets and variables → Actions
   - New repository secret
   - Name: `GITHUB_TOKEN`
   - Value: ваш токен

### 3. Создание иконки (опционально)

Создайте файл `icon.ico` для исполняемого файла (256x256 пикселей).

## 📦 Создание релиза

### Автоматический релиз (рекомендуется)

1. Создайте тег новой версии:
```bash
git tag v2.2.0
git push origin v2.2.0
```

2. GitHub Actions автоматически:
   - Соберет исполняемый файл
   - Создаст ZIP архив
   - Опубликует релиз
   - Загрузит файлы

### Ручной релиз

1. Зайдите в репозиторий → Releases
2. Нажмите "Create a new release"
3. Укажите тег версии (например, `v2.2.0`)
4. Напишите описание релиза
5. Загрузите ZIP архив с программой

## 🔧 Управление режимом обслуживания

### Включение режима обслуживания

1. В корне репозитория создайте файл `maintenance.json`:
```json
{
  "enabled": true,
  "message": "Проводятся технические работы. Программа временно недоступна.",
  "updated_at": "2024-01-01T12:00:00Z"
}
```

2. Закоммитьте и загрузите файл:
```bash
git add maintenance.json
git commit -m "Enable maintenance mode"
git push origin main
```

### Отключение режима обслуживания

Измените `enabled` на `false` и загрузите изменения:
```json
{
  "enabled": false,
  "message": "",
  "updated_at": "2024-01-01T12:00:00Z"
}
```

## 📊 Мониторинг и статистика

### Проверка работы обновлений

1. Запустите программу
2. Проверьте лог в консоли:
```
[12:00:00] Устройство зарегистрировано: abc12345...
[12:00:01] Актуальная версия: 2.2.0
```

### Статистика устройств

Программа автоматически собирает анонимную статистику:
- Уникальный ID устройства (только первые 8 символов)
- Версия программы
- Операционная система
- Время первого запуска

## 🎯 Типы обновлений

### Обычные обновления
```
v2.2.0 - Новые функции
```
Пользователи могут установить по желанию.

### Обязательные обновления
```
v2.2.0-mandatory - Критическое исправление
```
Или в описании релиза укажите слова:
- `mandatory`
- `critical`
- `security`
- `urgent`

Программа заблокирует работу до установки.

## 📱 Работа с пользователями

### Уведомление об обновлении

При запуске программы пользователи увидят:
- Диалог с информацией об обновлении
- Заметки к выпуску
- Кнопки "Установить" / "Отмена"

### Режим обслуживания

Если режим включен:
- Программа покажет модальное окно
- Работа будет заблокирована
- Проверка статуса каждые 30 секунд

## 🔒 Безопасность

### Приватность
- Только анонимная статистика
- IP-адреса не сохраняются
- Личные данные не собираются

### Защита
- Проверка подлинности файлов GitHub
- Цифровые подписи релизов
- Защита от вредоносных обновлений

## 🐛 Поиск проблем

### Ошибки API
```
Ошибка проверки обновлений: 403
```
- Проверьте лимиты API GitHub
- Убедитесь что репозиторий публичный

### Проблемы с версиями
```
Ошибка сравнения версий
```
- Используйте формат `vX.Y.Z`
- Проверьте номера версий

### Режим обслуживания не работает
- Убедитесь что файл `maintenance.json` в корне
- Проверьте JSON синтаксис
- Подождите 5 минут для обновления


## 🚀 Развертывание для команды

### Множественные разработчики

1. Добавьте разработчиков в репозиторий
2. Настройте права на создание релизов
3. Создайте правила для pull requests

### CI/CD Pipeline

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v3
      - name: Test
        run: python -m pytest tests/
```
